# Contributing

Thanks for your interest in Dynamic Dark Mode × Windows.

## Before starting
- Read the [README](README.md) and [roadmap](docs/roadmap.md).
- For substantial changes, open or find an issue first so scope and acceptance criteria are clear.
- Keep changes focused and avoid unrelated refactoring.

## Development workflow
1. Create a branch from the default branch (for example, `feat/protocol-prototype` or `fix/reconnect-after-resume`).
2. Make a small, focused change.
3. Add or update tests.
4. Run the relevant build and test commands locally.
5. Open a pull request using the template.
6. Address deterministic CI failures and triage AI review feedback.
7. Merge only when acceptance criteria and required checks are satisfied.

## Pull-request expectations
- Describe the problem and intended solution.
- Link related issues.
- Explain how it was tested and include manual test results where automated tests are not possible.
- Call out networking, permissions, security or privacy implications.
- Update documentation when behaviour or setup changes.

AI-generated review comments are advisory. The author remains responsible for validating suggestions and the maintainer makes the final decision.
